# KO Trans 2 버전 관리

## 단일 변경 지점

공개 버전은 **`src/KoTrans.App/KoTrans.App.csproj`의 `<Version>1.0.0</Version>` 한 곳**에서 관리한다.
사용자 화면에 표시할 문자열을 따로 수정하지 않는다. `AppVersionInfo`는 실행 중인 앱 어셈블리의 `AssemblyInformationalVersion`을 읽는다.

| 버전 | 목적 |
| --- | --- |
| `1.0.0` | 첫 정식 배포 |
| `1.0.1` | 기존 기능 버그 수정 |
| `1.1.0` | 하위 호환되는 개선 및 기능 변경 |
| `2.0.0` | 주요 비호환 변경 |
| `1.0.0-beta.1` | 정식 배포 전 공개 시험판 (필요한 경우) |

버전은 Semantic Versioning `MAJOR.MINOR.PATCH`를 따른다. 소스 변경만으로 매번 버전을 올릴 필요는 없지만, **새 공개 배포물의 버전은 명시적으로 검토하고 변경**한다.

## 화면 및 실행 파일

- 정식 빌드 `1.0.0`의 상태표시줄: **`Ver 1.0`**
- 같은 코드의 DEV-RUN 실행: **`Ver 1.0-dev`** (개발 실행 모드만 표시)
- 패치 배포 `1.0.1`: **`Ver 1.0.1`**
- 기능 버전 `1.1.0`: **`Ver 1.1`**
- 베타 `1.0.0-beta.1`: **`Ver 1.0-beta.1`**

`-dev`는 DEV-RUN 여부를 알려주는 **UI 표시일 뿐** 어셈블리나 배포 버전을 자동으로 변경하지 않는다.
상태표시줄 우측 자동 크기 영역(최대 110 DIP)의 툴팁은 전체 버전 및 제공된 빌드 메타데이터를 보여준다. 릴리즈에서 `SourceRevisionId`가 전달되면 실제 커밋 식별자가 포함된다. 없는 식별자는 생성하거나 추정하지 않는다.

상태표시줄의 왼쪽 메시지(저장 오류, 상태, OCR)는 필요한 너비만 차지하는 오른쪽 버전 영역을 침범하지 않고 한 줄로 생략 표시된다. **실제 원문은 변경되지 않으며**, 각 메시지에 마우스를 올리면 전체 내용을 볼 수 있다.

## 배포 절차

1. 릴리즈할 버전을 결정한다.
2. `src/KoTrans.App/KoTrans.App.csproj`의 `<Version>`만 변경하고 코드 리뷰·관련 회귀를 통과시킨다.
3. 해당 변경을 커밋한 후, **별도의 사용자 승인**으로 기존 `scripts/Publish-Release.ps1` 절차를 실행한다.
4. 배포 스크립트는 프로젝트에 명시된 버전과 실행 파일의 `ProductVersion`, `release.json`의 버전이 일치하는지 검사한다. `-Version` 인자를 전달해도 프로젝트의 버전과 다르면 실패한다.
5. 배포물 파일명은 예를 들어 `KOTrans2_v1.0.0_win-x64.zip` 형태로 관리할 수 있다. 패키지의 실제 파일 이름은 별도 배포 결정 사항이다.

상태표시줄 버전 표시를 추가했다고 자동 업데이트, 사용자 공지, 버전 서버, 원격 진단 수집 또는 릴리즈 작업이 활성화되는 것은 아니다.

## 검사

```powershell
pwsh -NoProfile -File scripts/Work.ps1 -BuildOnly
pwsh -NoProfile -File scripts/Test-Fast.ps1 -Suite Wpf
```

WPF Background 테스트는 버전 포맷, 빌드 메타데이터 툴팁, 기본/좁은 창에서 자동 너비 버전 컬럼과 긴 버전의 최대 너비, 긴 상태 메시지/저장 실패 생략 및 원문 유지 여부를 검사한다. 실제 GUI 시각 검증은 별도 Windows Desktop 단계에서 수행한다.
